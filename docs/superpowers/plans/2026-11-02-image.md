# `corundum-framework-image` and `image-preview` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new egui-free crate `corundum-framework-image` (decode, orientation, ICC → sRGB, thumbnails; `raw` and `webp` features) and an `ImagePreview` widget in `corundum-framework-gui` behind `image-preview`, exposed through the facade.

**Architecture:** The crate wraps `image` 0.25's pure-Rust decoders, applies EXIF orientation and an embedded ICC profile (moxcms) to produce sRGB RGBA8, and scales with `fast_image_resize`. `raw` reads a RAW file's embedded preview with `rawler`; `webp` encodes with `libwebp-sys`. The widget decodes on a worker thread sized to the pane and caches textures.

**Tech Stack:** Rust (workspace edition 2024), `image` 0.25 (no default features: jpeg, png, webp, gif, tiff), `moxcms`, `fast_image_resize`, `rawler` (LGPL-2.1, feature `raw`), `libwebp-sys` (bundled C, feature `webp`), egui (the gui crate's version).

**Spec:** `docs/superpowers/specs/2026-11-02-media-image-audio-design.md` (sections "Decisions", "`corundum-framework-image`", "The previews", "Facade", "Testing"). Why previews of non-app formats exist at all: `docs/file-previews.md`.

## Global Constraints

- The crate has no egui dependency; `cargo tree -p corundum-framework-image` shows no `egui`.
- Licence MIT OR Apache-2.0; version 0.7.0, in release-plz's `corundum` version group.
- `raw` and `webp` are off by default. The `raw` feature's doc (Cargo.toml comment and crate doc) says rawler is LGPL-2.1 and an app turning it on takes on its terms; `deny.toml` gets a per-crate exception for `rawler` (and only it) with that reason.
- Output is always sRGB, RGBA8, orientation applied. `thumbnail` never enlarges.
- `Limits::default()` = `max_bytes: 512 MiB`, `max_pixels: 200_000_000`; checked from the header before pixels are allocated.
- HEIC/HEIF, AVIF, ORF → `Error::Unsupported`. A decoder panic → `Error::Decode`.
- Strings the user reads are Fluent messages in `crates/corundum-framework-gui/locales/{en,ja}/corundum.ftl`, keys `corundum-preview-*`.
- Every task: `cargo fmt --all`, `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`, and the tests it names.

## Review Focus

- A phone photo with EXIF orientation 6 or 8 must come out upright in both `decode` and `thumbnail` (and in the preview). Task 1 pins it.
- A wide-gamut photo (Display P3 ICC) must be converted, not passed through as if sRGB. Task 2 pins it.
- A small image (e.g. 200×100) asked for at 2048 must stay 200×100 — no blur from enlarging. Task 2 pins it.
- A crafted header claiming 100 000 × 100 000 pixels must fail with `TooLarge` before allocating, not exhaust memory. Task 1 pins it.
- Scrolling through a folder in the explorer must never freeze the UI while a large image decodes, and a stale result must not overwrite the newer selection. Task 4 pins it.

### Task 1: The crate, sources, decoding, orientation and limits

**Files:**
- Create: `crates/corundum-framework-image/{Cargo.toml,README.md,src/lib.rs,src/decode.rs,src/error.rs}`, `crates/corundum-framework-image/tests/decode.rs`
- Modify: `release-plz.toml` (add the crate to the `corundum` group), root `Cargo.lock`

**Interfaces:**
- Produces:
  ```rust
  pub enum Source<'a> { Path(&'a Path), Bytes { bytes: &'a [u8], ext: Option<&'a str> } }
  pub struct Image { pub width: u32, pub height: u32, pub rgba: Vec<u8> }
  pub struct Limits { pub max_bytes: u64, pub max_pixels: u64 }   // impl Default (values above)
  pub enum Error { Unsupported, Decode(String), TooLarge, Io(std::io::Error) } // thiserror, Display
  pub fn decode(source: Source, limits: &Limits) -> Result<Image, Error>;
  ```
  `decode` detects the format from the bytes (`image::guess_format`), the extension only as a tie-break; reads the dimensions and checks `limits` first; decodes with `image::ImageDecoder`, reads its `orientation()` and applies it (`DynamicImage::apply_orientation`); converts to RGBA8. HEIC/HEIF/AVIF magic → `Unsupported`; any format `image` was built without → `Unsupported`. Wrap the decode in `std::panic::catch_unwind` → `Decode("decoder panicked")`. (ICC comes in Task 2: leave a clearly named hook, e.g. a private `icc_profile()` read that Task 2 uses.)

- [ ] **Step 1: Write the failing tests** in `tests/decode.rs`. Fixtures are made in the test with `image`'s encoders (dev-dependency with `jpeg`, `png`, `gif`, `tiff`, `webp` encoders), plus a helper `jpeg_with_orientation(w, h, o)` that splices an APP1 Exif segment (Orientation = `o`) after SOI.

```rust
#[test] fn each_format_decodes_to_rgba() { /* 4x3 image as jpeg, png, gif, tiff, webp(lossless) → width 4, height 3, rgba.len() == 48 */ }
#[test] fn orientation_is_applied() {
    for (o, dims) in [(1,(40,20)),(3,(40,20)),(6,(20,40)),(8,(20,40))] {
        let img = decode(Source::Bytes { bytes: &jpeg_with_orientation(40, 20, o), ext: Some("jpg") }, &Limits::default()).unwrap();
        assert_eq!((img.width, img.height), dims);
    }
}
#[test] fn a_mirrored_orientation_flips_pixels() { /* o=2: a 2x1 jpeg/png? — use png with eXIf chunk or the jpeg helper with a left-red/right-blue image; assert the left pixel is blue-ish */ }
#[test] fn heic_and_avif_are_unsupported() { /* minimal ftyp boxes "heic" and "avif" → Err(Error::Unsupported) */ }
#[test] fn garbage_is_a_decode_error() { /* 100 random bytes with ext "jpg" → Err(Decode(_)) or Err(Unsupported) — assert it is not Ok and does not panic */ }
#[test] fn a_huge_header_is_too_large_before_decoding() { /* PNG IHDR claiming 100_000 x 100_000 → Err(TooLarge) */ }
#[test] fn a_file_path_source_reads_the_file() { /* write the png to a tempdir, Source::Path */ }
#[test] fn an_over_large_file_is_too_large() { /* Limits { max_bytes: 10, .. } on a 100-byte png → TooLarge */ }
```

### Task 4: `ImagePreview` in corundum-framework-gui (`image-preview`)

**Files:**
- Create: `crates/corundum-framework-gui/src/preview/mod.rs`, `src/preview/image.rs`, `src/preview/tests.rs`
- Modify: `crates/corundum-framework-gui/Cargo.toml` (feature `image-preview = ["dep:corundum-framework-image"]`), `src/lib.rs` (`#[cfg(feature = "image-preview")] pub mod preview;`), `locales/{en,ja}/corundum.ftl`, the gui README's feature table

**Interfaces:**
- Consumes: `corundum_framework_image::{thumbnail, Source, Limits, Error, Image}`.
- Produces: `pub struct ImagePreview` with `ImagePreview::new() -> ImagePreview` and `pub fn ui(&mut self, ui: &mut egui::Ui, path: &Path)`.
  - Target size: `min(2048, ceil(max(available.x, available.y) * pixels_per_point))`, rounded up to the next of 256 / 512 / 1024 / 2048 so a resize does not re-decode.
  - One worker thread (spawned lazily) takes the latest request only; a result whose (path, modified time, size) is not the one currently shown is cached but not shown.
  - Cache: the last 8 decoded textures by (path, modified time, size).
  - While working: a spinner, centred. `Unsupported` → the file icon (`icons::file()`) and `corundum-preview-unsupported`; `TooLarge` → `corundum-preview-too-large`; other errors → `corundum-preview-failed` with `$reason`.
  - Drawn fitted in the available rect, aspect kept, never enlarged past its pixel size / pixels_per_point.
  - New strings (en / ja): `corundum-preview-unsupported` = `This file can't be previewed.` / `このファイルはプレビューできません。`; `corundum-preview-too-large` = `This image is too large to preview.` / `この画像は大きすぎてプレビューできません。`; `corundum-preview-failed` = `Couldn't read this file: { $reason }` / `このファイルを読めませんでした：{ $reason }`.

- [ ] **Step 1: Write the failing tests** in `src/preview/tests.rs`, drawing frames without a window as `explorer/tests.rs` does (accesskit on, `ctx.run_ui`):
  - `a_picture_shows_a_spinner_then_the_image`: a 64×32 PNG in a tempdir; first frame contains a spinner (no image texture); then frames until (≤ 5 s) a texture of 64×32 is registered/drawn (check the context's texture manager or the `Image` widget's response).
  - `a_newer_selection_wins`: request path A (a large image, e.g. 3000×3000) then path B (small) on the next frame; after the worker is idle the shown texture is B's.
  - `an_unsupported_file_says_so`: a `.heic` stub → the label `This file can't be previewed.` appears.
  - `the_strings_exist_in_both_languages`: the three keys resolve in `en` and `ja` (use the crate's `i18n::check` helpers as other modules' tests do).

- [ ] **Step 2: Run to see them fail** — `cargo test -p corundum-framework-gui --features image-preview preview` → compile errors.

- [ ] **Step 3: Implement** per the Interfaces. Keep egui calls on the UI thread only; the worker sends `(key, Result<Image, Error>)` over a channel and requests a repaint (`ctx.request_repaint()` via a cloned `egui::Context`).
