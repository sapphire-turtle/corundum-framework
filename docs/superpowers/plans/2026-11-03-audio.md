# corundum-framework-audio and the audio preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new crate `corundum-framework-audio` (no egui) holding asteria-music's playback engine, made generic over the queued item, and `AudioPreview` in the gui crate, which plays a picked audio file in the detail pane.

**Architecture:** The code moves from asteria (`music/crates/asteria-music-gui/src/player/`, at asteria `main`), keeping its tests. What is asteria's stays there: the HTTP opener (`feed.rs`'s `HttpOpener`, `stream.rs`, `test_server.rs`), `QueueEntry`, `Endpoint`, `Quality`. The engine becomes `Engine<T: QueueItem>`; the decoding thread becomes `spawn_feed`, fed by any `Source`; `FileOpener` plays local files. The device (cpal) is behind the `cpal` feature. `AudioPreview` hands the app's one `Player<PathBuf>` a queue of one file.

**Tech Stack:** Rust 1.99 / edition 2024; symphonia 0.6.1, ogg 0.9.2, opus-pure 0.2.2, rubato 5.0.1, cpal 0.18.2, rtrb 0.3; egui (gui crate only).

**Spec:** `docs/superpowers/specs/2026-11-02-media-image-audio-design.md` (sections "corundum-framework-audio", "The previews", "Facade", "Testing").

## Global Constraints

- The new crate is `crates/corundum-framework-audio`, version `0.7.0`, `license = "MIT OR Apache-2.0"`, wired the same way `corundum-framework-image` was (workspace member, `release-plz.toml` group, README tables, CI clippy loops, a no-egui `cargo tree` gate).
- No egui in `corundum-framework-audio`, with any features.
- Features of the audio crate: default (decoding, resampling, the engine, `FileOpener`, `Player`), `cpal` (the real device; brings cpal and rtrb), `test-support` (the fakes). `cpal` and `test-support` are off by default.
- Dependency versions as asteria's workspace pins them: `symphonia = { version = "0.6.1", default-features = false, features = ["flac", "mp3", "aac", "alac", "isomp4", "ogg", "vorbis", "pcm", "wav"] }`, `ogg = "0.9.2"`, `opus-pure = { version = "0.2.2", default-features = false }`, `rubato = "5.0.1"`, `cpal = "0.18.2"`, `rtrb = "0.3"`.
- The rules stay: `RESTART_AFTER_MS = 3_000` ("previous" restarts a track after 3 s of play), `MAX_SKIPS = 3` (three unplayable tracks in a row stop playback), the output ring `RING_MS = 200`.
- Threads are named `corundum-audio-player` (the engine) and `corundum-audio-decode` (a feed); the preview's probe worker `corundum-audio-probe`.
- Nothing plays on its own: picking an audio file shows the controls; playing starts on the button (spec decision 6).
- The preview has no queue: its play sends `Command::Replace { items: vec![path], start: 0 }` (spec decision 5).
- symphonia is MPL-2.0, which `deny.toml` already allows; `cargo deny check` stays clean with no new exceptions.
- No test writes outside a `tempfile` directory; no test needs a sound device.

## Review Focus

1. **The file is gone, renamed or unreadable when play is pressed** (or the probe met it so): the pane shows the reason ("Couldn't read this file: …") and stays responsive; nothing panics. → Task 5 `a_missing_file_shows_the_error_after_play`.
2. **Play on file B while A is playing**: B replaces A (one track in the queue), A's decode thread ends. → Task 3 `replacing_the_one_track_queue_plays_the_new_file` (asserts the old feed's thread is gone).
3. **No sound device at all** (a headless Linux, a phone with none): the play press ends in `PlayerError::Output`, shown in the pane, with no panic; `Player::spawn` itself never needs a device. → Task 5 `no_device_shows_the_output_error` (FakeOutputs refusing to open).
4. **A file that is not audio** (a `.txt`, a JPEG named `.mp3`): the probe fails, the pane says it can't be previewed, and no play button is offered. → Task 5 `a_file_that_is_not_audio_offers_no_play`.
5. **Seeking a file that is not the one playing**: the seek bar is disabled for it, so no `Seek` reaches the player for another track. → Task 5 `the_seek_bar_is_off_for_a_file_not_playing`.

## Decisions this plan makes (the spec leaves them open)

- **`QueueItem`** replaces asteria's `QueueEntry` inside the engine: `Clone + PartialEq + Debug + Send + 'static`, with `fn title(&self) -> String` (for `PlayerError::Unplayable`) and `fn duration_ms(&self) -> Option<u64> { None }` (the tag's length, used until the decoder knows). `PathBuf` implements it (title: the file name, lossy). The preload key compares items with `PartialEq` instead of asteria's `ItemId`.
- **`Command::Reset`** replaces `SetEndpoint`/`SetQuality`: it does what `SetEndpoint` did minus telling the opener an endpoint (skips = 0, empty queue, no current, halt, no error, `opener.clear()`, preload forgotten). An opener's own settings (asteria's server and quality) are the opener's to hold, shared with the app; sub-project 3 does that in asteria.
- **`Opener<T>`** keeps `open`, `preload`, `clear`, and loses `set_endpoint`/`set_quality`.
- **`Source`** (in `decode`) is what decoding reads: `Read + Seek + Send + Sync` with `fn byte_len(&self) -> Option<u64>` and `fn canceller(&self) -> Option<Box<dyn Fn() + Send + Sync>> { None }`; implemented for `std::fs::File`. symphonia's `MediaSource` stays private (an adapter wraps a `Source`).
- **`Watch`** (in `feed`) is how a fetch under a feed reports itself: `fn status(&self) -> SourceStatus` with `SourceStatus::{Ready, Waiting(Wait), Failed(TrackError)}`. A file has none. asteria's `Stream` will implement it (sub-project 3).
- **The preview keeps the old track playing** when another file is picked; the new file shows its own play button, and pressing it replaces what plays.
- **`Player::spawn` takes a repaint callback** (`impl Fn() + Send + 'static`) instead of an `egui::Context`; the 250 ms position throttle stays.

## Out of scope (sub-project 3, in asteria)

asteria-music moves onto this crate: its `HttpOpener` implements `Opener<QueueEntry>` with its endpoint and quality shared with the app (applied with `Command::Reset`), `Stream` implements `Watch` and `StreamReader` implements `Source`; `QueueEntry` implements `QueueItem`; its own `player` module shrinks to those.
