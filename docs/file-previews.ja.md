# corundum が、アプリの目的外のファイルまでプレビューする理由

> Language: [English](file-previews.md) | **日本語**

corundum のファイルエクスプローラーと詳細ペインは、それを使うアプリが本来扱わないファイルも表示・再生する。asteria-music のライブラリにある JPEG、sapphire-sync のフォルダーにある FLAC、そしていずれは PDF、プレーンテキスト、Markdown のメモも。アプリの目的だけを基準にすれば、これは合理的ではない。音楽プレーヤーが写真を描く理由はないし、形式が増えるたびに、本来なら小さく保てるフレームワークにコードと依存が増える。それでも corundum がそうする理由をここに残す。形式を足すたびに同じ議論を繰り返さないためである。

## 理由：アプリのデータは、ふつうのフォルダーである

corundum の上のアプリは、正本となる独自のデータベースを持たない。データは利用者が選んだフォルダーと、その中のふつうのファイルである。

- asteria のライブラリは、写真や音楽のディレクトリで、横にサイドカー、プレイリスト、ジャケットが並ぶ
- sapphire のワークスペース（sapphire-sync など）は、利用者自身のファイルのディレクトリで、機器のあいだで同期される

そのフォルダーを隠すものはなく、ほかのファイルが入ることを止めるものもない。音楽のフォルダーにはブックレットのスキャン、アルバムのキューシート、`notes.txt` が入り、写真のフォルダーには旅行のチケットの PDF が入り、同期しているフォルダーには利用者が置いたものが何でも入る。**これは通常の利用の範囲であり、正すべき誤りではない。** アプリはそうしたファイルを隠さず、自分のファイルと並べて一覧に出す。隠せばアプリの中のフォルダーとディスク上のフォルダーが食い違い、アプリの中でファイルを移動・改名・削除する人は、自分が動かすものを見えていなければならないからである。

一覧に出た以上、利用者が最初に問うのは「これは何か」である。その答えを出す場所が詳細ペインなので、アプリが目的とする形式に限らず、無理なく答えられるファイルにはすべて答える。

## これで許すこと、その限度

- **プレビューできる形式が増えることを歓迎する**：まず画像と音声（asteria がどのみち必要とする）、続いて PDF、プレーンテキスト、Markdown などの文書を、Rust のクレートで現実的に扱える範囲で
- **プレビューは見るためのもので、編集するためのものではない**：表示、再生、スクロールはここに置く。編集、注釈、変換は置かない（それはアプリ、または別のアプリの仕事）
- **形式ごとに機能フラグを付け、既定では切る**：要らないアプリはそれなしでビルドでき、corundum の既定のビルドは今と同じ小ささのまま
- **重い、または扱いにくい依存が要る形式は待つ**：純 Rust のデコーダーを優先する。良い純 Rust のものがなければ、C のライブラリを同梱する `-sys` クレートを機能フラグの後ろに置くのは許す。システムへのインストールが要る依存や、ライセンスがすべてのアプリを縛る依存は入れない
- **知らない形式、扱えない形式にも答える**：名前、大きさ、種類、日時と、「システムのアプリで開く」操作を出し、詳細ペインを空にしない

## これを使っているもの

- [画像と音声](superpowers/specs/2026-11-02-media-image-audio-design.md)：`corundum-framework-image`、`corundum-framework-audio`、ウィジェット `image-preview` / `audio-preview`
- [アプリが渡す内容の詳細ペインプレビュー](superpowers/specs/2026-11-05-detail-pane-previews-design.md)：ファイルの場所に関わらず、アプリがバイト列またはリーダーを渡す。`FilePreview` と `InfoCard` は機能なしで使え、音声は `ContentOpener` で起動した `Player<Content>` で再生する
- [テキスト、Markdown、PDF、日時](superpowers/specs/2026-11-05-text-markdown-pdf-datetime-design.md)：`text-preview` がテキストファイルを読み取り専用で表示する。文字コードは推定し、`FilePreview` はテキストの拡張子にこれを使う。`markdown-preview` は Markdown を整形して読み取り専用で表示し、クリックされたリンクは `PreviewResponse::link` でアプリに返す（開くかどうかはアプリが決める）。`FilePreview` は `.md` と `.markdown` にこれを使う。`pdf-preview` は PDF を 1 ページずつ、前へ・次へのボタンで表示する（最大 500 ページ。64 MiB を超えるファイルは開かない）。描画は純 Rust（hayro）でワーカースレッドで行う。ファイルに埋め込まれていないフォントはシステムの CJK フォントで代用し、標準 14 フォントは描画できる。パスワードで保護された PDF はページの代わりにメッセージを表示する。テキストの選択と検索はできない。`FilePreview` は `.pdf` にこれを使う
